# Data dictionary and provenance

All rows are generated by `generate_data.py`, seed 42 for history and seed 84 for scoring. Accounts and customers have one-to-one grain in this example; they do not reuse the SQL project identifiers or balances.

| Field | Definition | Model input? |
|---|---|---|
| account_id, customer_id | Synthetic identity, unique per snapshot | No |
| snapshot_date | Prediction observation date | Split only |
| days_past_due | Starting delinquency, 0–89 days | Yes |
| credit_score | Synthetic score, 420–820 | Yes |
| monthly_income | Synthetic monthly dollars; about 2.5% missing | Yes |
| balance | Synthetic outstanding dollars | Yes |
| utilization | Synthetic credit utilization fraction, 0–1 | Yes |
| missed_payments_6m | Simulated count before snapshot | Yes |
| portfolio | Credit Card, Auto, Personal Loan, Medical | Yes |
| outcome_end_date | Snapshot +90 days | No |
| future_90dpd | Simulated 90+ DPD event during next 90 days, binary | Target only |

The outcome is sampled from a logistic formula using starting attributes and an unobserved random shock. It is not derived from observed account trajectories. Missing income is introduced after simulation and imputed using training medians only. Scoring accounts omit outcome columns entirely. Historical outcome horizons finish by March 31, 2026; scoring snapshots are June 30, 2026.
